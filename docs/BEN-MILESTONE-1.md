## Consumer migration (coordinator-requested contract corrections)

- **Shaw / private imports:** wrap `CandidateBatch` in `NormalizedImportEnvelope`. Provide owner/source context, private `SourceRecord` metadata, one `evidenceRecords` entry per new evidence item, and one stable fact key plus immutable source-identity endpoints for each observed link, relationship, and affiliation. `candidateIndex` addresses the current batch array; it is not the durable key. Stable fact keys and external-record keys are owner/source scoped. Immutable source identities are `(sourceId, platform, externalId)`, and allow identity undo without rewriting original endpoints. Metadata refs must be opaque, not filesystem paths or signed URLs; raw payloads stay private outside Git. A batch lacking endpoint provenance must stay unavailable/pending, never invent an endpoint identity.
- **Reimports / storage:** `(scopeId, sourceId, batchId)` is the retry key, bound to a canonical payload digest. Exact retries return the prior outcome; changed content under the same retry key conflicts. New batches may revise stable external-record/fact keys, preserving prior evidence/record revisions and source-identity provenance. Existing evidence IDs are immutable; changed evidence requires a new ID. Durable transaction enforcement is an adapter prerequisite, not implemented by this library.
- **Affiliations / Shreev:** candidate `current` accepts boolean/null; absence normalizes to null in the envelope validator. Current employment cannot be inferred from absence. Canonical affiliations already carry boolean/null. Organization matching needs a confirmed true affiliation and supporting evidence. Role and current-employment criteria need corresponding actual support; unknown location, role, opportunity availability, and other constraints stay unknown/unsupported. Runtime validation checks structure and references, not natural-language truth.
- **Nicholas / construction events:** `BATCH_COMMITTED` arrays are ID upserts, applied atomically from `baseGraphVersion` to `graphVersion`. Destructive source deletion, identity reprojection or access changes emit `SNAPSHOT_INVALIDATED`; cancel search/playback, discard the cached graph and reload through authorized graph access. `removedSourceIds` lists removed sources only for `SOURCE_REMOVED`. Storage removes source records/evidence and rebuilds all dependent projections in the same transaction before emitting invalidation. Do not attempt source deletion by interpreting the legacy limited removed-person/edge arrays. Those remain for compatibility and are validated against before/after snapshots.
- **Nicholas / search replay:** final `SearchResult.paths` is authoritative; hydrate the path map before replay. `PATH_SELECTED` may reference these paths even if corresponding candidate trace events were omitted. Delivered search sequences start at 0 and are contiguous; assign sequence after trace sampling. Retain start, selected paths and completion within the event cap. Ignore exact duplicate deliveries; conflicting duplicates or sequence/version gaps require reload. Truncation counts describe omitted computation traces, not sequence holes. Construction poll pages use a monotonic job sequence; callers check persisted cursor continuity. Never invent missing events.
- **Identity review:** `IdentityLinkRequest` selects an explicit identity and expected/next person mapping (including null for unlink). `IdentityRevertRequest` selects a decision with graph version and idempotency key. `IdentityLinkDecision.nextPersonId` now permits null. Persist append-only decisions, compare expected mapping/version atomically, and return 409 if a later reassignment conflicts with reversal. These are contracts/validators only; execution and UI remain deferred.

Additional validator constraints requiring producer awareness: IDs use bounded opaque ASCII syntax; scores are finite [0,1]; UTC timestamps use seconds or millisecond precision; display URLs require HTTPS without credentials/query/fragment; evidence arrays on consequential claims are nonempty; identities only map to people after confirmation; follow/co-participant observations cannot form the default search prior. Paths are simple, directed, rooted, and limited to six hops. Score factors must agree with route-v1 arithmetic. Authenticated empty-contact graphs still include the real session root Person. No dangling root exception exists.

## Verified scope and trust boundaries

Tests use isolated anonymous identifiers only and are never imported by application code. They cover invalid shapes/scores/dates, reference and source violations, pending identity assignments, source provenance, simple paths and score factors, event binding, identity request boundaries, unauthenticated/cross-scope reads, stale versions, server caps, malicious engine events, missing dependencies, import staging authorization and non-echoing errors.

The auth adapter must verify session expiry/revocation and derive actor identity server-side. The read adapter must enforce owner/scope predicates in a consistent transaction and return display-safe text and authorized records. Schemas exclude raw fields and risky URLs but cannot prove free text contains no private data or prove an upstream claim is true. Private-only mode rejects pooled scopes/sharing contexts. Never wire request body actor/root/context values into trusted ports.

The staging adapter must implement atomic version/ownership/policy checks, canonical-content idempotency and durable pending-review storage. Passing an `ImportPort` is an assertion that those requirements hold; the interface itself supplies no persistence. No committed graph events are emitted by staging. The engine's in-process deadline is cooperative, not an enforced worker timeout. Public HTTP payload limits, CSRF/cookies, rate limits, storage encryption, source removal transactions, review/revert execution, provider failures and durable restart behavior still require integration tests.
