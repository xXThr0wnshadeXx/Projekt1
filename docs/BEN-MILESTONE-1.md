## Consumer migration (coordinator-requested contract corrections)

- **Shaw / private imports:** wrap `CandidateBatch` in `NormalizedImportEnvelope`. Provide owner/source context, private `SourceRecord` metadata, one `evidenceRecords` entry per new evidence item, and one stable fact key plus immutable source-identity endpoints for each observed link, relationship, and affiliation. `candidateIndex` addresses the current batch array; it is not the durable key. Stable fact keys and external-record keys are owner/source scoped. Immutable source identities are `(sourceId, platform, externalId)`, and allow identity undo without rewriting original endpoints. Metadata refs must be opaque, not filesystem paths or signed URLs; raw payloads stay private outside Git. A batch lacking endpoint provenance must stay unavailable/pending, never invent an endpoint identity.
- **Reimports / storage:** `(scopeId, sourceId, batchId)` is the retry key, bound to a canonical payload digest. Exact retries return the prior outcome; changed content under the same retry key conflicts. New batches may revise stable external-record/fact keys, preserving prior evidence/record revisions and source-identity provenance. Existing evidence IDs are immutable; changed evidence requires a new ID. Durable transaction enforcement is an adapter prerequisite, not implemented by this library.
- **Affiliations / Shreev:** candidate `current` accepts boolean/null; absence normalizes to null in the envelope validator. Current employment cannot be inferred from absence. Canonical affiliations already carry boolean/null. Organization matching needs a confirmed true affiliation and supporting evidence. Role and current-employment criteria need corresponding actual support; unknown location, role, opportunity availability, and other constraints stay unknown/unsupported. Runtime validation checks structure and references, not natural-language truth.
- **Nicolas / construction events:** `BATCH_COMMITTED` arrays are ID upserts, applied atomically from `baseGraphVersion` to `graphVersion`. Destructive source deletion, identity reprojection or access changes emit `SNAPSHOT_INVALIDATED`; cancel search/playback, discard the cached graph and reload through authorized graph access. `removedSourceIds` lists removed sources only for `SOURCE_REMOVED`. Storage removes source records/evidence and rebuilds all dependent projections in the same transaction before emitting invalidation. Do not attempt source deletion by interpreting the legacy limited removed-person/edge arrays. Those remain for compatibility and are validated against before/after snapshots.
- **Nicolas / search replay:** final `SearchResult.paths` is authoritative; hydrate the path map before replay. `PATH_SELECTED` may reference these paths even if corresponding candidate trace events were omitted. Delivered search sequences start at 0 and are contiguous; assign sequence after trace sampling. Retain start, selected paths and completion within the event cap. Ignore exact duplicate deliveries; conflicting duplicates or sequence/version gaps require reload. Truncation counts describe omitted computation traces, not sequence holes. Construction poll pages use a monotonic job sequence; callers check persisted cursor continuity. Never invent missing events.
- **Identity review:** `IdentityLinkRequest` selects an explicit identity and expected/next person mapping (including null for unlink). `IdentityRevertRequest` selects a decision with graph version and idempotency key. `IdentityLinkDecision.nextPersonId` now permits null. Persist append-only decisions, compare expected mapping/version atomically, and return 409 if a later reassignment conflicts with reversal. These are contracts/validators only; execution and UI remain deferred.

Additional validator constraints requiring producer awareness: IDs use bounded opaque ASCII syntax; scores are finite [0,1]; UTC timestamps use seconds or millisecond precision; display URLs require HTTPS without credentials/query/fragment; evidence arrays on consequential claims are nonempty; identities only map to people after confirmation; follow/co-participant observations cannot form the default search prior. Paths are simple, directed, rooted, and limited to six hops. Score factors must agree with route-v1 arithmetic. Authenticated empty-contact graphs still include the real session root Person. No dangling root exception exists.

## Corrective boundary review

The follow-up corrects four independently reproduced defects in the first milestone:

- Import retries now authorize actor/source and bind trusted context first, normalize the envelope without consulting the current graph, and compute its canonical SHA-256 digest. `ImportPort.lookupRetry` resolves an existing receipt before version/evidence checks. Equal payload returns the previous outcome with `duplicate:true`; changed payload returns 409. Object-key order is ignored, array order remains significant, omitted affiliation `current` normalizes to null, and `expectedGraphVersion` is excluded from the digest. New imports still require the expected graph version and current references. If concurrent work invalidates preflight, a second authorized receipt lookup resolves a just-committed retry. Adapter `stage` must atomically recheck the receipt before version/reference validation under a per-key transaction lock, and persist pending data plus receipt together; no actual database implementation is supplied. Both adapter methods must recheck current source ownership/access/policy, including revocation.
- Immutable source endpoints now canonicalize temporary IDs and matching authorized `existingPersonId` aliases. Either reference is accepted for the same source identity. Conflicting existing assignments and self-links disguised by aliases are rejected.
- Search output must exactly match the validated resolver goal and targets under canonical JSON comparison. Target array order is the resolver's order and must be preserved by the engine; object property order is irrelevant. Engine path ranking is unaffected. Duplicate resolver target people are rejected before engine invocation.
- `BATCH_COMMITTED` now applies ID upserts and supported removals to every before-snapshot collection and requires exact reconstruction of all after-snapshot entity collections (collection order is irrelevant). Empty/partial deltas cannot hide edits. Identity, organization, evidence or source deletions require `SNAPSHOT_INVALIDATED`, as do root, coverage or schema changes absent from the delta DTO. Overlapping upsert/removal IDs are rejected. Before/after snapshots must already be validated and authorized by the caller.

Focused regressions cover successful retries after graph advancement/evidence persistence, changed payload conflicts, authorization before receipt lookup, concurrent receipt races, alias equivalence, unrelated cached goals/targets, target ordering, incomplete deltas, supported removals and required invalidation. Checks: 93 tests pass, strict typecheck and library build pass. Production adapters and cross-track integration remain deferred. Do not publish this corrective commit until coordinator review.
